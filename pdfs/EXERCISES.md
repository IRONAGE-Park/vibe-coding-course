# 바이브코딩을 시작하기 전에 — 연습문제 원자료

> 슬라이드(12~20p)에는 4개 반영: 축제 일정 모음(바로 가능, 자체 제작 사례) / 보도블록(연습 ②) / 취소표(연습 ③) / 버스 도착정보(연습 ④).
> 나머지 사례는 시간이 남을 때 추가 토론용, 또는 유인물로 활용.

## 진행 방식 (슬라이드 반영됨)

각 사례를 질문으로 던지고 청중과 토론한 뒤 판단 슬라이드로 함께 답 내리기.

핵심 프레임 — 세 가지 질문:

> ① 만들 수 있는가? ② 만들어도 되는가? ③ 만들면 실제 문제가 해결되는가?

---

## 유형 1. 컴퓨터가 구현할 수 있는가 (기술·데이터의 한계)

| 사례 | 판단 | 슬라이드 |
|---|---|---|
| 축제·행사 일정 모음 사이트 | 바로 가능 — 공개 데이터 + 보여주기 = 컴퓨터의 본업 (자체 제작 사례) | ✅ 연습 ① |
| 위험한 보도블록 자동 탐지 | 조건부 가능 — 사진·신고·센서로 컴퓨터가 '볼 수 있게' 해야 | ✅ 연습 ② |
| 어르신 약 복용 확인 앱 | 알림·기록은 가능, 실제 복용 여부 확인은 어려움 | 예비 |
| 다음 달 매출 정확 예측 | 정확한 예측은 불가, 데이터 기반 추정(오차 포함)은 가능 | 예비 |
| 버튼 누르면 하천 쓰레기 청소 | 물리적 행동 불가 — 신고·배정·연결은 가능 | 예비 |
| 청년이 떠나지 않게 만드는 서비스 | '정착'은 사회적 목표 — 구체 기능으로 재정의 필요 | 예비 (문제정의 챕터와 연결) |

## 유형 2. 만들어도 되는가 (정책·권한의 한계)

| 사례 | 판단 | 슬라이드 |
|---|---|---|
| 여러 사이트 리뷰 수집 서비스 | 자동 수집 금지 약관·개인정보·콘텐츠 권리 문제 | 예비 |
| 취소표 자동 구매 프로그램 | 기술은 가능, 매크로 금지 약관·공정성 문제 | ✅ 연습 ③ |
| 직원 메신저 분석 퇴사 예측 | 동의 없는 수집·분석은 개인정보/노무 문제 | 예비 |
| 얼굴 인식 행사 출석 기록 | 민감정보 — 동의·보관·삭제 기준 없이는 운영 불가 | 예비 |
| 지원사업 자동 신청 대행 | 초안 작성까지만 — 본인확인·전자서명·최종 제출은 본인이 | 예비 |

## 유형 3. 만들면 해결되는가 (해결의 한계)

| 사례 | 판단 | 슬라이드 |
|---|---|---|
| 일자리 정보 앱 → 청년 정착? | 정보 접근은 해결, 일자리 부족은 해결 못함 | 예비 (팀 주제와 직결) |
| 관광 안내 앱 → 관광객 증가? | 정보 정리와 관광할 이유 만들기는 다른 문제 | 예비 (팀 주제와 직결) |
| 버스 도착정보 앱 → 교통 불편 해결? | 불확실성은 해결, 버스 부족은 그대로 | ✅ 연습 ④ |
| 복지정보 앱 → 사각지대 해소? | 정보는 제공, 신청 과정의 장벽은 남음 | 예비 |
| 불편 신고 앱 → 위험시설 수리? | 발견은 하게 하지만 처리(인력·예산)는 못함 | 예비 |

## 기타 사례 (유형 1·감각의 한계 — 추가 토론용)

- 악취 발생 지역 자동 탐지 (냄새 센서 없음)
- 사진 한 장으로 건물 안전 판정 (보이지 않는 정보 필요)
- 글만으로 상대방 속마음 판정 ("괜찮아"의 다섯 가지 의미)
- 교통약자 "항상 안전한 길" 내비 (현실은 계속 변함 — "현재 데이터상 접근 가능성 높은 길"로 표현)
- 위급 상황 완벽 감지 (간접 신호로는 확정 불가 — "확인이 필요한 상태"로 전달)

## 아이디어 구체화 프레임 (2교시 기획서와 연결)

사회적 목표 → 입력 / 처리 / 출력 / 현실의 행동으로 분해:

예: "청년들이 지역을 떠나지 않게 하는 앱" (너무 추상적)
→ "지역 취업 준비 청년이 자신의 조건에 맞는 채용공고와 주거지원 정책을 한 번에 찾기 어렵다"

- **입력**: 희망 직무 · 경력 · 희망 지역 · 주거 필요 여부 · 연령/자격
- **처리**: 채용공고 검색 · 자격 비교 · 주거정책 연결 · 마감일 정리
- **출력**: 신청 가능한 공고 · 지원사업 · 필요 서류 · 마감일
- **현실의 행동**: 청년이 지원 → 기업이 채용 → 기관이 주거지원 → 정착 지원 지속
