## 2. 원론을 얼마나 뺄 것인가 — 14장에서 2장으로

전수 분석 결과 **삭제 20장 · 압축 17장 · 유지 11장**입니다. 다만 "원론을 다 빼자"가 아닙니다. 정확히 두 장만 남깁니다.

**남기는 것**

1. **"도구는 계속 쉬워져 왔고, 지금은 자연어"** (현 6장 사다리 그래픽 + 8장 문구)
   수준 편차가 큰 방에서 "나는 못 할 것 같다"가 실습 최대 리스크입니다. 이 한 장이 그걸 정면으로 없앱니다.
2. **용어 3개 정의** (LLM / AI Agent / Vibe coding을 한 장으로)
   하루 종일 반복해 쓸 공통 어휘입니다. 정의를 안 맞추면 이후 모든 설명에서 되묻는 비용이 생깁니다. 원론이 아니라 운영 비용 절감입니다.

**빼는 것**
컴퓨터의 탄생 이유, ENIAC, 컴퓨터공학 소개, Waterfall/Agile 비교, 도구 4종 개별 설명(실습 단계로 이동), 간지 6장 중 5장.

**빼면 안 되는 것 (원론처럼 보이지만 아님)**
11장 CAN/CANNOT과 12장 획득·가공 기준은 팀이 2.5시간짜리 MVP 범위를 스스로 자를 때 쓰는 유일한 도구입니다. 축소가 아니라 강화 대상입니다.

## 3. 방법론을 무엇으로 채울 것인가

40분 안에 전달 가능하고 창업팀에게 실효가 있는 것만 추렸습니다.

| 넣을 것 | 왜 | 실습 | 소요 |
|---|---|---|---|
| 왜 지금 문제 정의인가 (위 1절 근거) | 코딩 시간을 왜 앞에 안 쓰는지 정당화 | — | 5분 |
| PG 우물 vs 사막 — "지금 당장 누가 원하나" | 시장 규모부터 말하는 습관을 즉시 교정 | — | 4분 |
| Tarpit 아이디어 (YC) | 10팀 중 다수가 해당될 가능성이 큼 | 자가 진단 1분 | 4분 |
| **The Mom Test 3규칙** | 오후에 서로에게 바로 써먹을 수 있음 | **롤플레이 5분** | 10분 |
| **PR/FAQ 축약판** | 결과물이 오후 MVP 제작 프롬프트로 직결 | **작성 5분** | 8분 |
| PSST의 P로 연결 | 오늘 만든 문제 정의가 곧 정부 사업계획서 1-1 문항 | — | 3분 |

**뺄 것.** Design Thinking 풀코스(40분에 불가능하고 근거도 약함), 정식 PR/FAQ(5~15시간 소요), 주 1회 인터뷰 습관화(하루 워크숍과 불일치).

**주의.** Paul Graham의 조언은 "유기적 아이디어가 없으면 만들어내지 말라"로 귀결됩니다. **평가 기준으로만 쓰고, "지금 아이디어를 만들어내라"는 용도로 쓰면 안 됩니다.**

## 4. 사례를 무엇으로 바꿀 것인가

지금 사례는 대학생 지역문제 해결용이라 창업 맥락이 약합니다. 대체 후보입니다.

| 후보 | 내용 | 왜 맞는가 |
|---|---|---|
| **야장맵 / 에그토스트랩** | Claude Code + Codex로 3주, MAU 6만 | 오늘 쓰는 것과 같은 도구, 실제 사용자 확보 |
| **거지맵 / 최성수** | Codex로 주말 이틀, 누적 246만 | "이틀"이라는 시간 감각이 오늘 2.5시간과 이어짐 |
| **러브버그맵** | 1일 미만, 제보 1.3만 건 | 하루 안에 되는 규모의 실물 증거 |
| **앱빌챗 박현중 인터뷰** | AI로 만든 앱 3,100만 개 중 실제 출시율 **0.4%** | 46장 교체용. 실명 실패 사례 대신 쓸 수 있는 안전한 반증 |

마지막 것이 특히 좋습니다. "만들기는 쉬워졌지만 대부분 출시조차 못 한다"는 숫자가 강의 전체 주장을 한 방에 뒷받침하면서, 실명 사업을 실패로 단정하는 위험도 피합니다.

## 5. 제안하는 새 구성 — 17장 30분

| 청크 | 내용 | 장수 | 시간 |
|---|---|---|---|
| A. 왜 지금, 무엇으로 | 동기 1장 + 어휘 1장 + 스택 1장 | 5장 | 8분 |
| B. 만들 수 있는 문제를 고르는 법 | CAN/CANNOT → 판정 기준 → 라이브 판정 2회 → 세 관문 | 5장 | 10.5분 |
| C. 좋은 문제로 다시 쓰기 | **네 칸 틀** → 팀 활동 → 쪼개기 → 사례 대비 | 7장 | 11.5분 |

**중심 슬라이드는 현 45장 "입력 · 처리 · 출력 · 현실의 행동" 네 칸입니다.** 지금은 사례 뒤에 묻혀 있는데, 팀이 2.5시간 내내 되돌아볼 유일한 틀이라 3.5분을 배정해 앞으로 끌어올릴 것을 권합니다.

**강의 안에 hands-on 1회를 심습니다.** 30분 내내 듣기만 하면 이후 팀 작업이 백지에서 시작됩니다. 팀별 문제 문장을 여기서 확정해두면 "기본 제작 1시간" 구간이 곧바로 굴러갑니다.
